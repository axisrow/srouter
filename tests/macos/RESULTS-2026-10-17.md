# Проверка uninstall в одноразовой macOS VM — 2026-10-17

Исходная версия: `d6566af2901a87f14cc04369f788c97694cb850a`.
Исправления: ветка `fix/uninstall-restore-and-purge`.
Среда: macOS 26.6.2, Apple VirtualMac, Python 3.13, Homebrew 7,
отдельная копия ВМ без общих папок. Рабочий proxy stack хоста не переключался.
Исходная ВМ оставлена выключенной. Реальные конфиги/ключи/сырые снимки в git не входят.

## Что воспроизведено в исходной версии

- После частичной ошибки удаления dnsmasq уже помечался unmanaged, хотя служба ещё
  работала; повторный uninstall оставлял её.
- Вывод об успешном откате не означал выгрузку watchdog: агент оставался и после reboot.
- Удалялся host-route, который существовал до установки srouter.
- Существовали потери исходных настроек и метаданных: удаление managed-значений само
  по себе не восстанавливает прежние пользовательские значения.

## Проверка исправлений

Выполнены install → reinstall → uninstall, повторный uninstall и отдельный
`uninstall -y --purge --remove-deps`. Финальное подтверждение интерактивного
удаления отменено в отдельном тесте: до отмены системных изменений не произошло.

| Независимая проверка | Результат |
| --- | --- |
| `.zshrc`, `.gitconfig`, Claude settings, VS Code settings, PPP ip-up | Все 5 совпали с исходными целиком, включая owner/mode/ACL/xattrs |
| Ручной DNS | Исходный список восстановлен, в том числе после reboot |
| Host-route, существовавший до установки | Сохранён при uninstall |
| Метаданные Homebrew после root-запуска dnsmasq | 35 путей проверены, расхождений нет |
| Обычный `-y` | Конфиги, state, бэкапы и зависимости сохранены |
| `--purge --remove-deps` | rc 0; state/legacy config удалены; xray, privoxy, dnsmasq удалены |
| Пакет, установленный до srouter | pcre2 сохранён; автоматический autoremove отключён |
| Собственные launchd jobs после reboot и ожидания | Отсутствуют; 18 проверок gui/system |
| PF anchors после reboot | Оба ruleset пусты, чтение успешно |
| Служебная запись Codex | Отсутствует; `/var/empty` сохранён |

Основные системные сценарии шли через SSH с предварительным `sudo -v`:
адаптер заменял только osascript transport, реальные PF/DNS/launchd/Homebrew/файлы
не подменялись. GUI-авторизация удаления учётной записи проверена отдельно
окончательными `provision_codex_user`/`deprovision_codex_user` без адаптера:
создание rc 0 → собственный диалог sysadminctl → TCC Allow → удаление rc 0 →
независимая проверка отсутствия. При отказе или таймауте успех не сообщается.

Оказалось, что sysadminctl может вернуть 0 при ошибке авторизации. Вложенный запуск
через повышенный osascript теряет нужный контекст. Прямой `interactive` использует
штатную авторизацию; на пароль и отдельный TCC-запрос отведено 180 секунд.

## Автоматические проверки и пределы

Финальный прогон: `pytest -n 2 -q` — **3300 passed, 13 skipped**.
`ruff check .`, `git diff --check` и синтаксическая проверка изменённых модулей — успешно.

Проверки исходного DNS, восстановления сервисов, конфликтующих поздних правок,
shared/preexisting dependencies, ошибок stop/readback/state-write, сохранения
данных восстановления и ссылок в чужие каталоги покрыты регрессионными тестами.
Для macOS ACL/xattrs и поведения `mv -h` использована реальная файловая система
в пользовательском временном каталоге без root-команд.

Сценарий ранее запущенного стороннего root-dnsmasq и все сочетания сторонних
изменений покрыты моделями команд, но отдельно целиком в ВМ не повторены.
GUI-установки всех необязательных wrapper-приложений не проверялись: в госте
не установлены Claude/Codex; их файловые контракты проверены тестами.

Для старой установки без сохранённых оригиналов восстановить неизвестные прежние
настройки невозможно. Uninstall сохраняет такие данные и сообщает о неполном
откате, вместо угадывания DNS или удаления чужих файлов.

Docker Desktop запущен; образ собран из исправленной ветки штатным

- Новые регрессии install/uninstall и связанные CLI/Codex-проверки внутри Linux:
  **72 passed, 2 skipped** (0.54 s); пропущены две проверки метаданных macOS.
- Docker-native `.dockerignore` canary с искусственными секретными файлами:
  **1 passed** (5.58 s), запуск с хоста из чистого `git archive` коммита.

Три пропуска основной приёмки: реальный Claude/macOS, git-ignore (git metadata
исключены из образа), Docker-canary (Docker CLI/socket отсутствуют внутри образа).
Canary отдельно успешно выполнен с хоста. Первый его запуск в рабочем worktree
безопасно пропустился из-за существующего bootstrap-конфига; чистый архив позволил
проверить Docker-фильтрацию без удаления или подмены этого файла.

Приёмочные и регрессионные контейнеры удалены через `--rm`. Docker проверяет
CLI и контракты замен системных команд; фактические PF/launchd/macOS DNS проверены
в ВМ, как описано выше.
