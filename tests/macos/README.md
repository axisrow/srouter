# Проверка удаления на macOS

Только одноразовая **macOS VM**. Docker проверяет CLI с заглушками, но не ядро PF,
launchd, DNS и реальные права файлов. Рабочий Mac для этих команд не используется.
Оригинал ВМ оставить выключенным, тестировать копию; сохранить выключенный диск
перед первой установкой, чтобы повторять сценарии с одинакового состояния.

Использовать только пример конфигурации с тестовыми адресами/ключами. Нужны Python
с Flask, Homebrew и Command Line Tools (`/usr/bin/git --version` должен работать).
Если macOS запросит Python доступ к локальной сети или администрированию, оператор
принимает решение **внутри тестовой ВМ**. Скрипты эти разрешения не обходят.

## Исходное состояние

Сохранить ручной DNS, отдельный host-route, пользовательские настройки `.zshrc`,
`.gitconfig`, Claude/VS Code и существующий `/etc/ppp/ip-up`. Включить в файлы
необычные отступы, права, ACL и extended attributes. Отдельно проверить пустые и
отсутствующие файлы. Для сценария зависимостей оставить заранее установленный
неиспользуемый пакет: удаление srouter не должно вызвать Homebrew autoremove для него.

Независимый снимок не импортирует модули приложения. Нужен действующий sudo-ticket:

```sh
sudo -v
SROUTER_VM_ACCEPTANCE=1 python3 tests/macos/snapshot.py --root "$PWD" --out /tmp/before.json
```

Снимок сохраняет коды возврата, файлы с hash/owner/mode/ACL/xattrs, DNS, proxy,
маршруты, PF, учётную запись, процессы и оба варианта brew launchd-label. Ненулевой
код чтения означает неизвестное состояние, а не успешное отсутствие.

## Матрица

1. Установить исходную версию, снять `installed`, выполнить её uninstall. Сохранить
   вывод и rc. Снять состояние сразу, спустя минимум **330 секунд** и после reboot
   с входом пользователя: живые StartInterval/RunAtLoad-агенты могут вернуть настройки.
2. Вернуть выключенную копию к исходному диску. Повторить с исправленной версией.
   Выполнить install → reinstall → `uninstall -y`: исходные настройки должны вернуться,
   данные/бэкапы/зависимости остаться. Повторный uninstall должен быть идемпотентным.
3. Повторить с `uninstall -y --purge --remove-deps`: удаляются данные приложения и
   только записанные собственные формулы; заранее установленные и общие остаются.
4. Повторить с ранее запущенными сервисами, чужими настройками и правками после
   установки. Вернуть прежний сервис; конфликтующие поздние правки сохранить и
   сообщить ненулевой rc. При ошибке остановки/восстановления не удалять state/backup.

После каждого сценария сравнить реальные снимки, не только строку «Откат завершён».
Изменения счётчиков PF, PID и времени сравнивать по смыслу; исходные пользовательские
файлы — целиком, включая метаданные. Проверить, что DNS отвечает и прямой выход жив.

При автоматизации через SSH допустимо заранее подтвердить sudo вместо GUI-моста;
это проверяет реальные системные эффекты, но **не проверяет GUI-аутентификацию**.
В отчёте явно указать этот предел. Полный CLI и пользовательские запросы проверить
отдельно в гостевом Terminal. После теста отключить временный SSH и удалить его ключ.

Снимки и реальные журналы хранить вне git. Не прикладывать state с ключами или VPS.
